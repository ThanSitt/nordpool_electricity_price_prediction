## 1. 模型评估是什么？为什么必须做？

**模型评估（model evaluation）** = 拿"模型没见过的数据"去考它，看它预测得准不准。

### 1.1 为什么不能用训练数据评估？

打个比方：学生平时做过的练习题（训练数据 train set），考试时再考一遍当然分数高——但那不代表真实水平。所以要用**没做过的题**考：也就是**测试集（test set）**。

### 1.2 三种数据的分工

| 数据   | 英文           | 用途                                   |
| ------ | -------------- | -------------------------------------- |
| 训练集 | training set   | 让模型"学习"规律                       |
| 验证集 | validation set | 调超参数（hyperparameter）时用的"小考" |
| 测试集 | test set       | 最后"期末考"，只考一次，模型从没见过   |

> 本项目没有单独留验证集（训练时在 notebook 里用时间序列切分调参），`2.0_forecast_visualization.ipynb` 只负责最后的"期末考"——用**最后 20% 的时间**当测试集。

### 1.3 为什么时序数据要"按时间切分"而不能随机打乱？

因为**时间序列（time series）**有先后顺序：未来的信息如果混进训练（数据泄漏，data leakage），模型等于"偷看了答案"。所以切分是：

```
前 80%（过去）→ 训练       后 20%（未来/最近）→ 测试
2023 – 2025-05            2025-05 – 2025-12
```

在代码里就是：

```python
train_end = n - int(n * 0.20)   # 前 80% 的结束位置
X_test  = X.iloc[train_end:]    # 取最后 20% 当测试
y_test  = y.iloc[train_end:]
```

## 3. 方面①：整体误差指标（metrics）

### 3.1 三个指标的含义

| 指标     | 英文全称                            | 公式                                    | 含义                       | 方向          |
| -------- | ----------------------------------- | --------------------------------------- | -------------------------- | ------------- |
| **MAE**  | Mean Absolute Error，平均绝对误差   | \$\frac{1}{n}\sum\|y-\hat{y}\|\$        | 平均每次差多少欧元         | 越小越好      |
| **RMSE** | Root Mean Squared Error，均方根误差 | \$\sqrt{\frac{1}{n}\sum(y-\hat{y})^2}\$ | 对大误差惩罚更重           | 越小越好      |
| **R²**   | R squared，决定系数                 | \$1-\frac{SS*{res}}{SS*{tot}}\$         | 解释了价格波动的百分之多少 | 越接近 1 越好 |

### 3.2 怎么读这三个指标

- **MAE 最好懂**：平均每个 15 分钟预测错 2.64 欧/MWh。
- **RMSE 和 MAE 的差距**：RMSE ≈ 7.9，MAE ≈ 2.6，RMSE 明显大于 MAE → 说明**存在少数很大的误差**（因为 RMSE 先平方再开方，会放大巨大误差）。这些大误差通常来自**价格尖峰（price spike）**时刻——模型很难预判突然的暴涨。
- **R² = 0.974**：模型解释了 97.4% 的价格波动，对这类预测任务已经非常强。

### 3.3 代码要点（对比两模型）

```python
MODEL_NAMES = ['lightgbm_v3_1', 'xgboost_v4']   # 要对比的两个模型
for name in MODEL_NAMES:
    meta = joblib.load(MODELS_DIR / f'{name}.pkl')     # 加载模型（含 feature_cols）
    yp = meta['model'].predict(X_test[meta['feature_cols']])  # 用各自的特征列预测
    # 记录 MAE / RMSE / R² ...
comp = pd.DataFrame(results).T     # 转成"模型为行、指标为列"的对比表
```

> 关键点：两个模型各自**只用自己训练时的特征列**（`feature_cols`），保证评估公平且不报错。

### 3.4 指标对比柱状图（notebook 图 1.1）怎么看

图里对 MAE / RMSE / R² 各画两根柱子（一个模型一根），数值直接标在柱顶。
**怎么看**：在同一组里，柱子矮（MAE/RMSE）或高（R²）的就是更好的模型；直接看每组的数值高低即可，一目了然。

## 4. 方面②：时间走势拟合（实际 vs 预测折线图，notebook 图 1.2）

### 4.1 为什么选折线图

要回答"预测曲线跟得上真实曲线吗"，最适合把两条线画在**同一张时间轴**上看（时间序列折线图，time-series line plot）。

### 4.2 代码做了什么

```python
steps = 7 * 24 * 4            # 7 天 × 24 小时 × 4 个 15 分钟 = 672 个点
fig.add_trace(... y=y_test[:steps],  name='Actual', ...)   # 黑色粗线 = 真实价
fig.add_trace(... y=preds[name][:steps], name=name, ...)   # 两个模型的预测线
```

只画测试集**前 7 天**（672 个点）——全画会糊成一团，画 7 天足够看清细节。

### 4.3 怎么看

1. **整体形态**：预测线（蓝/橙）是不是基本贴着黑线（真实价）走？
2. **尖峰时刻**：价格突然冲高的地方，预测跟上了还是差很远？（模型通常跟不上尖峰）
3. **两个模型谁贴得更紧**：在波动大的地方，哪条线离黑线更近？
4. 一般结论：两模型都很贴近真实，LightGBM 略好——但肉眼只能看个大概，精确结论要看指标（方面①）。

## 5. 方面③：逐点一致性（散点图 + 对角线，notebook 图 1.3）

### 5.1 为什么选散点图

折线图看"走势"，散点图看"每一个时刻准不准"。横轴 = 真实价（actual），纵轴 = 预测价（predicted）。如果预测完美，每个点都应落在 **y = x 对角线**上。

### 5.2 双面板代码要点

```python
from plotly.subplots import make_subplots
fig = make_subplots(rows=1, cols=2, subplot_titles=MODEL_NAMES)  # 一个模型一个面板
# 每个面板：散点 + 一条红色虚线 y=x
```

两个模型各占一个小图（subplot，子图），方便并排比较。

### 5.3 怎么看

1. **点是否聚集在对角线附近**：越靠近红色虚线越好。
2. **点的形状**：如果呈一条斜"带"，说明预测和真实强相关（好）；如果是"一团"，说明预测没抓住规律（差）。
3. **有没有系统性偏移**：
   - 点在对角线**上方** → 预测偏高（over-predict，预测过度）
   - 点在对角线**下方** → 预测偏低（under-predict，预测不足）
4. **右上角/右下角**：高价格区往往散得开（因为尖峰难预测）。

## 6. 方面④：误差分布（残差直方图，notebook 图 1.4）

### 6.1 什么是残差（residual）

**残差 = 真实值 − 预测值**，也就是每个时刻的预测误差。

```python
residuals = y_test.values - y_pred
```

### 6.2 为什么选直方图（histogram）

把所有时刻的误差统计成一张分布图，就能看出误差的"性格"：有没有系统性偏差（bias，系统性偏移）、误差集中还是分散、有没有极端值。

### 6.3 怎么看（重要）

1. **中心是否在 0**：好的模型，误差围绕 0 对称分布。
   - 均值（mean）≈ 0 → 模型**没有系统性偏差**（不会整体高估或低估）。
   - 实测：LightGBM residual mean = 0.076，XGBoost = 0.078，都非常接近 0 → 两者都**无系统偏差**。
2. **对称性**：如果明显偏向一边 → 模型总是一个方向错。
3. **宽窄**：标准差（std）越小越集中（LGBM std 7.90 vs XGB 8.04，LGBM 略小）。
4. **长尾（long tail）**：两边的长尾巴 = 少数时刻错得特别多（通常是尖峰）——这是电价预测的固有难点。
5. 两个直方图叠加对比（半透明），能直观看出谁的分布更"瘦高"（集中在 0 附近）。

## 7. 方面⑤：可解释性（特征重要性，notebook 图 1.5）

### 7.1 什么是特征重要性（feature importance）

XGBoost / LightGBM 能告诉我们：**每个特征对预测的贡献有多大**（模型内部计算，通常是该特征被用来分裂节点的次数/信息增益）。

```python
imp = pd.Series(model.feature_importances_, index=feature_cols).sort_values().tail(20)
```

取**最重要 20 个**画横向柱状图（`orientation='h'` 横着方便读特征名）。

### 7.2 怎么看（结合本项目实测）

- LightGBM 的前几名里出现了 **V3.1 的新特征**：`fi_se_total_lag_96`（瑞典输电滞后）、`fi_se_total_lag_672`、`fi_ee_lag_672`（爱沙尼亚输电滞后）、`nuclear_change_1d`（核电日变化）——说明**新增的跨境输电和核电特征确实被 LightGBM 用上了**。
- XGBoost 的前几名更多是 `price_lag_1/2/4`、`price_rolling_*`、时间特征（season/hour）——说明 XGBoost 主要靠**价格自身的历史（自回归，autoregressive）**。
- 这个差异本身就是有意思的发现：**两个模型"思考"的侧重点不同**，可以在报告里讲。

### 7.3 用途

1. 确认模型"没有乱学"（重要特征是否符合直觉）。
2. 为后续特征工程（feature engineering）指方向。
3. 给报告/答辩提供"模型为什么这么预测"的解释材料。

## 8. 方面⑥：未来泛化——7天预测 vs 回填实际（notebook 图 2.1、2.2）

### 8.1 为什么必须看这一块（大学生项目最容易忽略！）

**测试集分数 ≠ 真实预测表现。** 原因：

- 测试集评估是"一步预测"（模型每次用真实的历史去预测下一步）。
- 而真实的 7 天预测是**递归预测（recursive forecasting）**：预测值会被当作"历史"喂回模型去预测下一步，**误差会累积**。
- 本项目实测过：V2.5 测试集 MAE ≈ 2.8，但线上递归预测的 MAE 要高得多（价格环境变化 + 误差累积）。

所以：**评估报告一定要补上"7 天预测准不准"这一块**，用 `predictions/*.csv` 里每天自动生成的预测，和**回填（backfilled）**的真实价对比。

### 8.2 预测 CSV 从哪来

`predictions/*.csv` 由 `src/predict_system.py` 每天自动生成（GitHub Actions 每天 UTC 11:00 跑）。每列含义：

| 列名              | 含义                     |
| ----------------- | ------------------------ |
| `run_date`        | 哪天跑的                 |
| `target_datetime` | 预测的是哪个时刻         |
| `predicted_price` | 预测价                   |
| `actual_price`    | 真实价（时间过去后回填） |
| `abs_error`       | \|实际 − 预测\|          |

### 8.3 图 2.1（所有模型的最新 7 天预测）怎么看

把所有模型最近一次的 7 天预测画在一起：

- 看哪些模型预测接近、谁是**离群**（outlier，明显偏离群体）。
- 点图例（legend）可单独隐藏/显示某条线，交互式查看。

### 8.4 图 2.2（两强对决：LGBM V3.1 vs XGB V4 预测 vs 实际）怎么看

- 只画 `lightgbm_v3_1` 和 `xgboost_v4` 最近一次 7 天预测（两条粗线）。
- 一旦真实价公布，就叠一条黑色虚线（实际值）。
- **怎么看**：预测线离黑色虚线越近越准；刚跑完的那几天实际价还没公布（虚线还没出现），过几天会自动补上。
- 这是对"哪个模型在真实未来预测中更可靠"的最直接证据。
