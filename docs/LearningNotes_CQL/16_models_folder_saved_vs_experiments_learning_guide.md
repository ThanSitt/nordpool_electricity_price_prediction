# 16. The `models/` Folder — saved vs experiments & the train/serve gap

> Date: 2026-08-15
> Related: `modelV3.1.ipynb`, `modelV3.1_live.ipynb`, `modelV4.ipynb`, `src/predict_system.py`
> 技术术语配中文注释。

---

## 0. TL;DR — 一句话

- `models/` 是**模型仓库**：所有训练好的 `.pkl` 模型都放这里。
- 它分成两个文件夹，代表**两种身份**：
  - **`saved/` = 生产模型** → 每日自动预测真正会加载使用（特征都能算出来）。
  - **`experiments/` = 实验记录** → 特征还没接进 `src/`，先存着，不能上线。
- **判断标准**：模型的特征 `src/features.py` 造不造得出来。造不出来 → 只能放 `experiments/`。
- `modelV3.1_live.ipynb` 是证明这个道理的**关键实验**（train/serve gap）。

---

## 1. `models/` 文件夹是做什么的？（模型仓库）

**作用**：存放所有训练好的模型文件（`.pkl`，用 joblib 保存）。

每个 `.pkl` 是一个**模型包**，包含三样东西（这是整个预测系统的核心契约）：

```python
{
    'model': 训练好的 XGBoost/LightGBM,   # 真正用来预测的"大脑"
    'feature_cols': [特征列名列表...],     # 预测时按这个顺序喂特征（顺序很重要）
    'step_min': 15,                        # 分辨率（15=15分钟，60=小时）
}
```

`src/predict_system.py` 的 `load_models()` 每天**扫描 `models/saved/*.pkl`**，
把里面所有模型自动加载来预测。所以：

> **新增模型不用改任何代码**——只要把 `.pkl` 放进 `saved/`，每日自动预测就会自动用它。

---

## 2. 为什么分 `saved/` 和 `experiments/`？（生产 vs 实验）

| 文件夹                | 身份         | 里面的模型                                             | 能否进每日预测                                     |
| --------------------- | ------------ | ------------------------------------------------------ | -------------------------------------------------- |
| `models/saved/`       | **生产模型** | v1 / v1.5 / v2 / v2.5 / v2.5.2 / **v2.5.3** + LightGBM | ✅ 能（特征都被 `src/features.py` 支持）           |
| `models/experiments/` | **实验记录** | **v3（网格）、v4（网格+核电）**                        | ❌ 暂不能（特征 `fi_*` / `nuclear_*` 不在 `src/`） |

### 2.1 为什么不能一律放 `saved/`？

因为 `predict_system.py` 造特征用的是 `src/features.py`。如果一个模型的
`feature_cols` 里有 `src/features.py` **造不出来的特征**（比如网格 `fi_*`、核电 `nuclear_*`），
那么线上预测时这些特征全是 **NaN**（缺失值）。

XGBoost / LightGBM **不会报错**（它们把 NaN 当缺失值处理），但：

- 模型训练时见过这些特征的真实值；
- 线上全变成 NaN → 相当于模型"被迫用没见过的数据分布" → **预测静默变差**。

> 这就是为什么"网格接入 src"当时做了又回退（`docs/LearningNotes_CQL/14_*`）：
> 代码和模型必须配套，否则会静默劣化。

### 2.2 什么时候能把实验模型"转正"？

只有满足**两个条件**，才能把模型从 `experiments/` 迁到 `saved/`：

1. `src/features.py` 能造出这个模型的所有特征；
2. `src/fetch_live.py` 能在线上实时抓到这些特征的原始数据（例如 Fingrid 网格/核电的实时数据）。

在这之前，实验模型只能放在 `experiments/` 当**记录**。

## 3. 为什么 V3.1 还有一个 `live` 训练笔记本？（train/serve gap）

这是最关键的一环：**"训练时有用" ≠ "线上能用"。**

### 3.1 逻辑链

```
modelV3.1.ipynb（完整实验）
  加网格 → MAE 2.7236 → 2.7152（有帮助 ✅）
  但用了 62 个特征，其中含 7 个"当期"网格流（fi_ee 等 = t 时刻实际测量值）
        │
        ▼ 致命点
  线上预测【未来】时刻时，t 时刻的实测流量还没发生 → 拿不到 → NaN
        │
        ▼
modelV3.1_live.ipynb（可行性测试）
  只保留线上真正拿得到的 6 个"滞后"网格特征（55 特征）重测
        │
        ▼
  结果：MAE 2.7416（+0.0180）→ 变差 ❌
```

### 3.2 结论

- 网格特征**训练时有用的部分（当期流）恰恰是线上拿不到的部分**；
- 线上可行的部分（滞后特征）反而没用；
- 这个差距就叫 **train/serve gap（训练/服务差距）**。

所以 `modelV3.1_live.ipynb` **不是多余的重复**，它是**决定"要不要部署"的证据**：
它证明了网格模型**不能**进 `saved/`、**不能**接 `src/`——这也正是你决定"网格不接入"的根本原因。

### 3.3 扩展到核电

同样的道理也适用于核电特征：

- `nuclear_power_mw`（当期）训练时有用，但线上预测未来时拿不到；
- 真正线上可用的是 `nuclear_lag_96/672`（滞后）；
- 所以 `xgboost_v4.pkl` 目前也放在 `experiments/`，等 `src/` 支持后再转正。

---

## 4. 关键收获（Key Takeaways）

1. **模型仓库 = `models/`**，`.pkl` 包三样东西：model + feature_cols + step_min。
2. **`saved/` = 能上线**（特征都能算），**`experiments/` = 只是记录**（特征没接进 `src/`）。
3. **放进 `saved/` 就会被每日自动预测使用**——所以放之前必须确认 `src/` 能造出全部特征。
4. **train/serve gap**：训练有用的"当期/未来"信息，线上往往拿不到；能用的通常是滞后/前瞻已知的信息。
5. **实验笔记本（如 `*_live`）的价值**：在投入部署前，先证明"能上线且有用"，避免浪费。
